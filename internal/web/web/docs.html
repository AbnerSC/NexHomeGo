NexHome 联枢 使用文档

一站式内网节点守护工具 · 官网说明手册。本文档随系统一同部署，覆盖全部模块的每一项功能、表单字段含义、业务规则与常见问题的处理方式。

适用版本：v1.3.x 随系统部署 左侧支持关键词搜索

1. 快速开始

1.1 首次启动与登录

NexHome 是单进程、前后端一体的轻量服务：启动一个 Go 单二进制、默认只占用一个端口，所有任务与配置持久化在程序运行目录下的 data/nexhome.db（SQLite）。

  1. 启动服务（Docker 或裸机二进制，见 第 15 章）。
  2. 浏览器打开 http://127.0.0.1:8090（默认端口 8090）。
  3. 首次启动时系统会随机生成 16 位高强度初始密码并打印到控制台（形如「首次启动，已生成随机初始密码……」，含大小写字母、数字与符号）。系统不存在任何固定默认密码，请到控制台/容器日志读取。
  4. 输入密码登录，立即到「系统设置 → 修改登录密码」更换为自己知道的密码。
安全提示初始密码只打印一次，不落操作日志；丢失需按「忘记密码」流程重置。修改密码后所有已登录会话全部失效，需重新登录。

1.2 登录安全机制
机制说明
失败锁定同一来源 IP 连续登录失败达到上限（默认 3 次）后，该 IP 临时锁定 30 分钟；成功登录后计数清零。阈值与时长可在「系统设置 → 登录安全设置」调整（次数 1~100，时长 1~1440 分钟）。失败计数为进程内存态，重启进程后归零。触发锁定时会向通知中心已启用渠道推送 auth.lockout 告警。
单点登录系统强制单点登录：新设备登录会自动注销之前的会话，旧标签页再次请求将被踢回登录页。
会话有效期登录后颁发的 Token 有效期 24 小时，过期后需重新登录。
接口鉴权除登录与登录状态检查外，所有 /api/** 接口都需携带 Token（请求头 X-Token 或查询参数 token）。查询参数形式仅对 GET / HEAD 生效且响应带 Cache-Control: no-store（便于浏览器直接下载证书/备份，同时避免 Token 经地址栏与中间缓存外泄）；其余请求请使用请求头。
锁定计数口径失败次数按TCP 直连对端地址统计，不采信 X-Forwarded-For 等客户端自报头；否则每次换一个伪造 IP 即可无限次爆破。

1.4 使用前建议的三步顺序
  1. 「系统设置 → 服务商凭证配置」录入阿里云 AccessKey（若使用 DDNS / 证书 DNS01 自动验证 / ESA 同步）。
  2. 「通知中心」建好至少一个可用渠道并「测试发送」通过，后续所有告警才有出口。
  3. 「系统设置 → 访问与安全设置」按需改端口、开 HTTPS、设安全入口。

2.4 网络测速

测量 浏览器 ↔ 本系统 之间的链路质量，不经任何外部测速服务器，因此可安全用于内网与穿透链路测试。

指标算法与说明
延迟小载荷连续 HTTP 往返，取中位数（代表链路典型往返，抗尖峰）；下方小字给出最低~最高区间。前两次请求作为握手预热不计入。
抖动P95 − P50（对应 ITU-T G.114 的网络性抖动 ipdv）。为保证样本量，至少采满 20 个样本或到最长窗口（两倍测量时长）为止，样本偏少时小字会标注「（偏少）」。
丢包率测量窗口内 5 秒未返回的请求计为一次丢失，按丢失/(成功+丢失) 计算百分比。
下载 / 上传速率6 路并发拉流/推流（等于浏览器同源 HTTP/1.1 连接上限），正式测量前先短时预热全部连接以排除握手与 TCP 慢启动；下载读流放在独立 Worker 线程中，避免页面卡顿干扰测量。结果显示为 Mbps。
  • 三个阶段（① 延迟/丢包 → ② 下载 → ③ 上传）各测 10 秒，顶部进度条按阶段权重单调推进并标注「预热/测量」。
  • 测速期间自动暂停仪表盘 15 秒刷新与顶栏 5 秒监控轮询，避免抢占连接与 CPU；中途切换页面不会打断测速，回到总览后数值与进度按缓存复原。
  • Worker 不可用的老浏览器会自动回退主线程读流，此时下行数值可能被主线程性能限制。

3. 网站导航

3.1 内外网地址智能切换

每个导航条目可同时维护内网地址与外网地址，页面根据当前访问来源自动挑选该展示哪一套。右上角三段按钮：自动 / 内网 / 外网，手动指定后点「自动」可恢复自动识别。

自动识别的优先级（从高到低）：

  1. 浏览器内网探测：配置了「内网探测链接」时，由浏览器直接探测该地址（如路由器管理地址）——可达即判定处于内网。此方式不受访问链路（域名、反向代理、回流）干扰，最准确。
  2. 服务端连接源 IP：按请求的真实来源 IP 判断内外网（即使面板通过两套域名访问也适用）。
  3. 主机名回退：以上均不可用时，按当前访问的 hostname 是否为 localhost / 127. / 10. / 192.168. / 172.16~31. 判断。

当前模式下若条目没有对应地址，会自动回退到另一套地址（两个地址允许只填其一），卡片提示中标注「回退」。

建议面板始终经互联网域名/反代访问时，服务端看到的源 IP 可能都是内网代理地址，此时务必配置「内网探测链接」提高判定准确率。

3.5 内网探测设置

管理视图中的「🔌 内网探测」用于填写探测链接（留空关闭）。填写后面板加载时会用 no-cors 请求该地址（不读取内容、带时间戳穿透缓存），超时或失败按不可达处理。

  • 建议填写内网特有地址（路由器、NAS 管理页），若其他局域网也使用该地址（如 192.168.1.1）可能误判为内网。
  • 面板经 HTTPS 访问时浏览器会拦截 http:// 探测链接（混合内容），请改填内网 https 地址，或经 http 访问面板。

4. DDNS 域名同步

4.1 功能说明

DDNS 模块按固定周期把当前 IP 写入域名解析记录，让域名始终跟随出口地址变化。直连阿里云云解析 DNS 与阿里云 ESA（边缘安全加速），无需额外 SDK 或中间服务。

页面列表列：任务（名称 + 服务商）、域名（主机记录.主域名 + 记录类型）、IP来源、定时同步（开关 + 间隔秒数）、当前IP（最近一次同步成功的 IP）、最近同步（状态徽标 + 时间）、操作（同步 / 编辑 / 删除）。数据每 10 秒自动刷新。

4.2 新增 / 编辑同步任务

点击右上「＋ 新增同步任务」，字段如下（带 * 为必填）：

字段必填说明
任务名称是便于识别的自定义名称。
服务商是阿里云DNS（云解析 DNS）或 阿里云ESA。切换为 ESA 时表单会额外出现「ESA 站点」选择区。
主域名是如 example.com（不带主机记录）。
主机记录是如 www、@、nas。最终记录为 主机记录.主域名。
记录类型—A（IPv4）或 AAAA（IPv6）。需与所选 IP 来源返回的地址族一致，否则同步会失败。
TTL（秒）—解析缓存时间，最小 60，默认 600。频繁变更 IP 时可调小，但过小会增加查询量。
IP 来源是公网接口自动获取 / 本机网卡 / 手动输入，详见 4.3。
网卡—仅「本机网卡」模式显示。留空 = 自动选择（取第一个非回环、支持广播的网卡）；下拉列表来自实时枚举，多网卡机器建议显式指定。
手动 IP条件必填仅「手动输入」模式显示且必填，用于 IP 固定但无法自动获取的场景。
阿里云凭证是下拉选择在「系统设置 → 服务商凭证配置」中维护的 AccessKey；选「手动填写 AccessKey」则需自行填 ID / Secret。下拉只列出与当前服务商类型匹配的凭证（ALIYUN_DNS / ALIYUN_ESA 都归属阿里云），已引用的配置在编辑时始终保留。
AccessKey ID / Secret条件必填仅在未选择凭证配置时显示必填。建议使用 RAM 子账号，仅授予 AliyunDNSFullAccess 或 ESA 解析相关权限。
ESA 站点条件必填仅服务商为 ESA 时显示。点「加载站点」由 ESA API 实时拉取，显示形如「站点名（SiteId: 1234567890，生效状态）」；若原 SiteId 已不在列表中，会保留该项并标注「当前站点，未在阿里云列表中找到」，避免编辑回显丢失。
同步间隔（秒）—最小 60，默认 300。
启用定时同步—停用后仍可手动点「同步」执行一次。

4.3 「预览即将同步的 IP」

表单中「IP 预览」区的按钮，按当前尚未保存的 IP 来源配置实时解析一次并绿色显示结果（失败时红色显示原因）。用于在保存前确认「本机网卡」选对了网卡、「公网接口」拿到的确实是出口公网 IP，避免把错误地址写进线上解析。

4.4 三种 IP 来源如何选
模式适用场景与注意
公网接口自动获取最常见。通过外部接口获取本机出口公网 IP，适用于宽带拨号动态公网 IP。注意：处于运营商 NAT（CGNAT）下时拿到的是共享出口地址，指向本机不一定可达，此时应改用 STUN 穿透（第 5 章）。
本机网卡本机拥有需要解析出去的地址（如专线公网 IP、IPv6 地址在网卡上）。可指定网卡，留空自动选择。注意：拿到的是内网地址时，公网解析将不可达。
手动输入地址由外部确定（例如配合 STUN 映射、或固定 another 主机地址）。不会自动变化，仅适合地址稳定的场景。

4.5 定时同步与手动同步
  • 定时同步：列表中每行的开关控制，开启后按「同步间隔」周期执行；关闭只保留任务配置。切换开关会立即生效并在短提示中反馈。
  • 手动同步：点行内「同步」按钮立即触发一次。同步为异步执行，页面会在 2 秒、6 秒后各刷新一次列表以显示最终状态（包含「记录已存在因而取消写入」等结果）。
  • 同步结果写入「最近同步」列：成功（绿）/失败（红，附原因）；「当前IP」列展示最近同步成功的地址。
写入策略目标记录已存在且值一致时按「跳过」处理，不会反复提交；记录值变化时才发起修改。

4.6 删除任务：会问是否连远程记录一起删

点「删除」先做常规二次确认，随后再弹一次询问：

  • 删除远程：同步删除服务商上的解析记录，之后再删本地任务。
  • 仅删本地：只删除本地任务配置，保留云端解析记录（适合把域名交给别的管理方式接管）。
注意选择「删除远程」后，若该记录正被证书 DNS01、代理站点等使用，将一并失去解析，请先确认影响。

4.7 常见问题
  • 报权限错误（Forbidden / NoPermission）：AccessKey 权限策略不足，需包含云解析 DNS（或 ESA）的读写权限；换用系统授权策略 AliyunDNSFullAccess 的 RAM 子账号。
  • 「加载站点」提示无可用站点：阿里云 ESA 尚未添加站点，请先到 ESA 控制台完成站点接入再回来创建任务。
  • 同步成功但域名不生效：多为 TTL 缓存未过期，等待一个 TTL 周期；或记录类型（A/AAAA）与实际 IP 地址族不匹配。
  • 公网接口获取失败：出口接口不可达或本机断网，任务会记为失败并保留上一次成功 IP，可改用「本机网卡」模式验证。

同步失败的具体原因可在「操作日志」的 DDNS 模块中查看。

5. STUN 端口穿透

5.1 能力与边界（先读这一节）

STUN 模块通过标准 STUN 协议在 NAT 设备上建立并保活映射，让没有公网 IP 的主机也能对外提供服务。穿透通道可承载 UDP / TCP / HTTP 数据传输。

三条必须知道的前提
① 任务「运行中」≠ 外网可访问，请以「可用性自测」列的结果为准。
② 对称型（Symmetric）NAT 纯 STUN 无法穿透，请改用路由器端口转发。
③ 受限锥形 NAT 仅允许已打洞的对端连入，需要在任务中填写「对端公网地址」由本端主动打洞。

穿透启动时会自动尝试 UPnP 端口映射（路由器 WAN 口为公网地址时即为权威入站通道）。在 CGNAT 或未启用 UPnP 的情况下，TCP 任务会按优先级自动降级选择出站通道：STUN 长连接精确映射 → 双链路模式（公共端点出站保活 + 同端口 STUN 短连接探测精确映射，对单事务型 STUN 服务器同样可复用）→ 端口保留兜底。

穿透成功后系统会自动做一次自测（映射保活 + 公网入站可达），之后可在操作列手动复测。列表数据每 5 秒自动刷新。

5.6 ESA 边缘安全加速同步

启用后，在穿透成功与映射地址变化时自动：把映射 IP 写入 ESA 的 DNS 解析记录、把映射端口写入 ESA 回源规则的 HTTPS 端口，实现「无公网 IP + 域名直连」的自动闭环。

配置步骤：启用 → 选择服务商凭证（阿里云）→「拉取站点」选择站点 →「拉取 DNS 解析记录」勾选要写入映射 IP 的记录 →「拉取回源规则」勾选要写入映射端口的规则。站点、记录、规则均由 API 实时拉取供勾选，不需要手工填 ID。

写入规则（重要）
① 只更新已勾选项，绝不新增或删除云端配置。
② 解析记录仅 A / AAAA 类型生效；多值记录、以及 IPv4↔IPv6 地址族不一致的记录不会被覆盖。
③ 回源端口仅 TCP 任务改动；UDP 任务的映射端口对 HTTPS 回源无意义，只同步解析记录。
④ 回源协议沿用线上现值，本功能只改端口。
⑤ 现值与目标一致时跳过写入。
⑥ 「全局」类型的回源配置不适用端口同步，勾选列表中不展示。

快照中已被云端删除的勾选项会以「线上未找到 · 只更新不新增」标记保留（保持勾选状态，便于取消），同步时自动跳过。同步失败只记日志并体现在「ESA 同步」列，不影响穿透本身，可点行内「ESA」手动补一次。手动同步弹窗按「解析记录 / 回源规则」逐条列出 原值 → 新值 与状态（已更新 / 跳过 / 失败）。

5.8 通知中心推送

启用后，在三种时机按勾选的通知渠道（可多选，渠道本身在「告警通知」页集中维护）发送通知：① 穿透成功；② 映射地址变化；③ 可用性自测确认失效（FAIL）。

  • 通知正文包含：任务名、协议、内网目标、外网映射地址、NAT 类型。
  • 投递结果写入「告警通知」页的最近发送记录，不落在任务行上。
  • 渠道被删除或停用时自动跳过，不影响穿透；已删除渠道在表单中仍会列出并标注「已删除 · 不会发送」，便于取消选择。
  • 保存后可点行内「🔔」试发一次，验证渠道勾选与投递链路。

5.9 流量统计

点行内「📊 流量统计」打开弹窗，查看该任务的穿透流量曲线，支持三个统计周期：按小时（近 24 小时）、按天（近 30 天）、按月（近 12 月）。鼠标悬停可查看具体时点数值。列表中的「流量」列展示累计转发字节数，按 KB/MB/GB 自动换算。

5.10 排错：TCP 任务运行中但外网仍访问不通
  1. 先点「📡 探测 NAT 类型」：对称型无法纯 STUN 穿透 → 改用路由器端口转发。
  2. 受限锥形 → 在任务中填写「对端公网地址」由本端主动打洞，或请对端配合互打。
  3. 确认主机防火墙已放行监听端口（Windows：允许 nexhome 通过「专用 / 公用网络」的入站规则）。
  4. 确认目标内网服务本身在监听且允许来自该地址的访问。
  5. 点「🔎 可达性自测」复核；结果仍为 FAIL 时到「操作日志」的 STUN 模块看详细原因。

8.1 原理与前提

向局域网广播 UDP 魔术包 唤醒已关机/休眠的主机。使用前需确认：

  • 目标主机网卡与 BIOS 已开启 Wake on LAN（部分机型还需开启「PCIE/关机供电」与「ErP 关」）。
  • 运行 NexHome 的机器与目标在同一广播域；跨网段/VLAN 需将广播地址指向对应子网的定向广播地址。
  • 魔术包无法穿过 NAT，从外网唤醒需配合端口转发或先唤起一台内网主机再由它转发。

9.3 HTTP01 与 DNS01 如何选
方式前提特点
HTTP01域名已解析到本机公网 IP，且公网 80 端口能访问到本服务（可经路由器端口转发）全自动，无需任何凭证；不支持通配域名。
DNS01能修改域名 TXT 记录无需开放入站端口，支持通配域名。域名托管在阿里云（云解析或 ESA）时可选凭证实现全自动；否则为半自动：看提示手动加 TXT 再点「完成验证」。

9.4 申请、手动 TXT 验证与续期
  • 申请 / 续期：按状态显示为「申请」或「续期」，点击后提示「申请已发起，请稍候刷新查看进度」（异步执行）。
  • 状态为待验证（PENDING_VALIDATION）时多出两个按钮：查看TXT（弹窗给出主机记录与记录值）与完成验证（提交给 CA 校验）。到域名服务商添加 TXT 并生效后再点。
  • 自动续期：开启后系统在到期前 21 天自动重跑一次签发流程。DNS01 选了阿里云凭证时无人干预即可完续；手动 TXT 方式每次续期都需人工再验一次，建议自动续期场景配好阿里云凭证。
  • 面板 HTTPS 使用的证书续期后会自动重启加载（见 第 14 章）；代理中心的 SNI 证书自动热加载，无需重启。

9.5 详情、下载与删除
  • 详情（仅已签发）：主体、颁发者、域名列表、生效/到期时间、序列号、SHA-256 指纹。
  • 下载（仅已签发）：弹窗提供三个链接 fullchain.pem（证书链）/ cert.pem（证书）/ domain.key.pem（私钥）。链接携带会话 Token，请自己保管私钥、不要外泄。
  • 删除：二次确认时明确提示「磁盘上的证书文件也会被清理」；若面板 HTTPS 正使用该证书，删除后 HTTPS 会不可用。
  • 列表「状态」列会直接展示失败原因摘要（窄列下可折行），便于定位。

9.6 签发成功 Webhook

以 Content-Type: application/json 的 HTTP POST 发送如下结构（签发/续期成功后自动触发，失败不影响证书，仅在日志告警）：

{
  "event": "certificate.issued",
  "taskId": "任务ID",
  "name": "任务名称",
  "domains": ["example.com", "www.example.com"],
  "notBefore": "生效时间(ISO8601)",
  "notAfter": "到期时间(ISO8601)",
  "keyPem": "-----BEGIN PRIVATE KEY----- ...",
  "certPem": "-----BEGIN CERTIFICATE----- ...",
  "fullchainPem": "完整证书链 PEM"
}
安全必提醒请求体含私钥，请仅推送到可信地址并使用 HTTPS；若接收端需校验来源，建议在网关侧配置固定 Token / 白名单。

9.7 常见问题
  • HTTP01 申请失败：确认域名已解析到本机公网 IP、公网 80 端口能转发到本服务；否则改用 DNS01。
  • 通配域名被拒：通配符必须用 DNS01；若选了阿里云自动验证，还需确认凭证对应该域名所在账号且 ESA 托管时已填 SiteId。
  • 一直停在待验证：TXT 未生效（查 _acme-challenge 记录）或未点「完成验证」。
  • 详细错误可在「操作日志」的 CERT 模块查看。

10. 代理中心（反向代理）

10.1 总体能力

独立监听端口的反向代理，对外提供 HTTP/1.1 + HTTP/2，按域名 + 路径前缀路由到内网后端。HTTPS 依据 SNI 自动匹配「SSL 证书」模块已签发的证书，证书续期后自动热加载。支持 WebSocket 透传、强制 HTTPS、IP 白名单、BasicAuth、限流与 nginx 风格磁盘文件缓存。

默认监听 80 / 443；功能默认关闭，开启后面板其余业务（非代理）流量不受影响。面板数据每 8 秒自动刷新。

10.2 服务设置与监听状态
字段说明
启用代理总开关，默认关闭。开启后才绑定端口。
HTTP 端口默认 80（1~65535）。
HTTPS 端口默认 443（1~65535）。
来源 IP 解析取值优先级：aliyun-esa-real-client-ip（ESA 自定义回源头）→ X-Forwarded-For（取链尾，即最近一跳代理所见）→ X-Real-IP → CF-Connecting-IP；全部缺失时回退 TCP 对端地址。

11. Docker 容器管理与运维

11.1 连接前提

本模块直连 Docker Daemon。两种接入方式：

  • 挂载 socket（推荐）：-v /var/run/docker.sock:/var/run/docker.sock，并设 DOCKER_HOST=unix:///var/run/docker.sock。
  • 远程 Daemon：环境变量 DOCKER_HOST 指向 tcp://主机:2375，需保证网络可达与权限。

未连接时，页面降级为「🐳 Docker 未连接」提示页，展示具体错误原因与可直接复制的 docker run 挂载示例；即使未连接也会每 10 秒重试，挂载好后无需重启面板。工具栏右侧常驻显示当前连接地址。

权限说明容器内进程需有 socket 读写权限（默认 root 满足）；非 root 用户需将其加入宿主 docker 组对应的 gid。报 Permission denied 即为此问题。

11.2 顶部统计卡

五张卡汇总宿主 Docker 整体概况：Docker 版本（含 API 版本、OS/架构）、运行 / 总容器、镜像（数量 · 占用空间）、卷（数量 · 占用空间）、宿主 OS（内核版本 · 总内存）。容器页每 10 秒、Compose 页每 15 秒自动刷新（仅重绘统计卡与数据行，保留工具栏/表头）。

13. 内存诊断

13.1 用途与使用思路

用于定位「内存突然上升且不释放」。推荐三步：先看实时内存分解判断涨在 Go 堆、协程栈还是运行时/RSS → 再点「分析内存跳变」自动找出曲线跳升的时间点 → 页面会把该时刻前后的 op_log 事件对齐展示，直接看到“是什么动作引起的”。

本页只统计本系统（进程）的内存占用（Go 运行时 + 进程 RSS），不展示宿主机整体内存；宿主机 CPU / 内存 / 虚拟内存请看顶部资源监控。

采样自本次进程启动，每 10 秒一个样本，运行越久时间线越完整。默认自动刷新已勾选（10 秒一次）。

双折线图：进程 RSS（青）与 Go 堆（绿）。纵轴满刻度自动为曲线峰值×1.1，图例显示当前值、样本数与时间跨度。鼠标悬停出现十字准线 + 气泡，给出该样本点的精确时间与两个值（靠近右缘时气泡自动翻到左侧避免溢出）。至少需 2 个样本才成图，否则提示稍后再刷新。

13.4 分析内存跳变

工具栏「分析指标」可选 进程 RSS（含运行时） 或 Go 堆，点「分析内存跳变」后生成四块结果：

  1. 结论摘要：时间跨度内从多少变到多少、净增多少 MB；若检测到跳变，指出最大单周期跳升发生的时间（如 42.3 MB → 78.1 MB，+35.8 MB）；曲线平稳时明确提示“未检测到明显的单周期跳升”。样本不足 2 个时提示无法定位。
  2. 跳变点前后日志：展示跳变时刻前后各 2 分钟的 op_log 记录（时间/模块/级别/内容，ERROR 红、WARN 橙）。
  3. 关键事件：自动挑出缓存加载 / 重启 / 监听启动等里程碑事件。
  4. 日志密度：每分钟条数的迷你柱状，悬停看具体分钟，并总结“共 N 分钟有日志，单分钟峰值 M 条”。

13.5 导出快照

「导出快照 JSON」把当前完整采样数据（实时分解 + 全部历史样本）下载为 nexhome-memdiag-<时间戳>.json，便于存档对比或提交给他人协助分析。

13.6 阅读建议
  • Go 堆涨而进程 RSS 不涨：多为堆内对象未回收，重点看 GC 次数/耗时与堆软上限 GOMEMLIMIT（若设置）。
  • 堆不涨但 RSS 涨：看协程栈与运行时合计（Sys）的增幅，并确认协程数是否异常增长（协程泄漏会持续占用栈内存）。
  • Go 堆贴近 GOMEMLIMIT 时运行时会加大 GC 力度（CPU 上升）以贴住软限；代理大文件下载走流式转发，磁盘缓存不占内存。
  • 容器限额建议 ≥512MB；频繁 OOM 先看本页确认是 Go 堆、协程栈还是运行时其他开销，再相应调整。

15. 部署与升级

15.1 Docker Compose 部署（推荐）

官方镜像 babyfly/nex-home（多架构 linux/amd64 与 linux/arm64）。典型 compose（host 网络 + docker.sock 挂载）：

services:
  nex-home:
    image: babyfly/nex-home:latest
    container_name: nex-home
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./data:/app/data
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      - TZ=Asia/Shanghai
      - DOCKER_HOST=unix:///var/run/docker.sock
    deploy:
      resources:
        limits:
          memory: 512m   # 推荐 512MB 以上
    ulimits:
      nofile: { soft: 65535, hard: 65535 }
    healthcheck:
      # 镜像无 curl，改用 bash /dev/tcp 探测端口
      test: ["CMD-SHELL", "exec 3<>/dev/tcp/127.0.0.1/8090 && echo -n '' >&3"]
      interval: 10s
      timeout: 3s
      retries: 3
      start_period: 20s

启动：docker compose up -d，然后访问 http://127.0.0.1:8090。

healthcheck 切勿用 curl运行镜像为精简 base（Go 静态二进制），不含 curl / wget，用 curl -f 会使容器始终处于 unhealthy。

为何用 host 网络：DDNS 需直接读网卡出口 IP、STUN 穿透与 UPnP 需真实网卡、代理要监听 80/443、WOL 需广播。若采用桥接网络，需自行做端口映射且部分能力（广播、UPnP、网卡 IP）会受限。

15.2 裸机二进制运行

产出为单个二进制文件，目标机无需安装任何运行时；有 Go 环境（Go 1.27+）时执行 go build -o nexhome ./cmd/nexhome 后直接 ./nexhome 运行。程序在运行目录自动创建：配置文件 data/nexhome.properties、数据库 data/nexhome.db、证书与上传目录等。初始密码同样打印到控制台。

可选环境变量（一般无需设置）：GOMEMLIMIT（Go 堆软上限，建议设为容器限额的一半左右）、GOMAXPROCS（限制可使用的 CPU 核数）；未设置时运行时按 cgroup 限额自动调节。

仅包含少量基础项（业务配置全部在 SQLite 中），首次启动自动生成：

  • 容器部署请挂载 ./data:/app/data（或命名卷），否则重建容器会丢失全部配置。
  • 备份两种途径：面板「系统设置 → 配置备份」导出一致性快照；或直接停容器后备份整个 data 目录。
  • 迁移：新机器起同版本镜像 → 把备份的 nexhome.db（或整个 data 目录）放入挂载目录 → 启动。注意证书保存目录与导航图标也在 data 下，建议整目录迁移。

15.5 升级
  1. 先在「系统设置 → 配置备份」导出一份快照。
  2. docker compose pull 后 docker compose up -d（镜像 tag 固定 latest 时先 pull）。
  3. 升级后首次启动会从控制台打印一次当前密码相关的初始化信息，已有数据库不会被重置，密码保持为上次设置的值。
  4. 若升级后页面样式异常，静态资源带 no-cache，一般强制刷新（Ctrl+F5）即可。

15.6 对外暴露的安全建议
  • 启用安全入口路径，避免面板根路径被扫描与爆破。
  • 保持失败锁定开启（默认 3 次 / 30 分钟），并及时配置通知渠道以收到 auth.lockout 告警。
  • 启用 HTTPS：先在 SSL 证书模块签发（HTTP01 需公网 80，否则用 DNS01），再在访问设置中开启。
  • 不要把 Docker 能力当对外接口暴露：docker.sock 等于宿主 root，代理站点不要反代面板到不可信网络。
  • 代理直连公网且开启白名单 / BasicAuth 时，保持「来源 IP」为自动或关闭；只有当前置反代固定在可信地址（内网段，或已加入「可信代理网段」的 ESA/CDN 回源段）时才可能采信转发头，不要为了省事设为“始终”，否则伪造 XFF 即可绕过白名单。

16. 常见问题（FAQ）

16.1 忘记登录密码
  1. 停止程序（或容器）。
  2. 删除 data/nexhome.db 中 app_config 表的 auth.password 行。
  3. 重启，系统将重新随机生成一个初始密码并打印到控制台，用该密码登录后立即改密。
注意上述做法仅影响密码一项；但若直接删整个数据库文件会丢失全部配置。因此强烈建议平时用「配置备份」定期导出。

忘记安全入口路径同样可通过查询/清空 app_config 中的访问配置项恢复（或直接换未设入口的备份库恢复）。

16.2 登不上：一直被锁定或反复回登录页
  • 提示锁定：该来源 IP 连续失败达上限。等锁定时长过去（默认 30 分钟），或重启进程（失败计数为内存态，重启即归零）。
  • 反复被踢回登录页：系统强制单点登录，另一台设备/标签页登录后会注销之前的会话；属正常行为。Token 有效期 24 小时，过期也需重登。

16.5 内存占得多 / OOM 重启
  1. 先看顶栏与「总览」的内存颜色（≥60% 橙、≥85% 红）确认趋势。
  2. 进「内存诊断」：Go 堆涨 → 看 GC 次数/耗时与堆软上限（GOMEMLIMIT，若设置）；堆不涨但 RSS 涨 → 看协程栈与运行时合计（Sys）的增幅，确认协程数是否异常增长。
  3. 结合「分析内存跳变」把跳升时间与 op_log 对齐，定位是哪个动作（代理大文件、批量任务、测速）引起。
  4. 适当上调容器内存限额（推荐 ≥512MB）；若 Go 堆长期贴住 GOMEMLIMIT（GC 变频繁、CPU 上升），考虑调高容器限额与 GOMEMLIMIT，或降低代理大文件并发。
